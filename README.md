# zahyou

天体写真から**いま望遠鏡がどこを向いているか**を割り出し、目標の天体へ
**どちらへどれだけ動かせばよいか**を教えてくれるプログラムです。

星図と写真を見比べて「たぶんこの星だろう」と推測する必要はありません。
矢印の向きにコントローラーを操作するだけで目標を導入できます。
インターネットの無い山の中でも動きます。

| | |
|---|---|
| 入力 | FITS / FIT / JPEG / PNG / TIFF（カラーでも動画の 1 コマでも可） |
| 出力 | 撮影時の向きの画像 + 北を上にした画像 + 赤経赤緯それぞれのずれ |
| 対応画角 | 4′ 〜 2000′（星図データを足せば 2′ まで）|
| 解析時間 | オンライン 約 10 秒 / オフライン 約 4 秒 |

詳しい説明は
**[導入・運用マニュアル v3（PDF・16 ページ）](天体画像解析プログラム「zahyou」導入・運用マニュアルv3.pdf)**
にあります。

| 項目 | 必要なもの |
|---|---|

## 5.〜7. オフラインでも使う場合

### 5. WSL を入れる

WSL（Windows Subsystem for Linux）は Windows の中で Linux を動かすしくみで、
オフライン解析のエンジンがこの上で動きます。

1. スタートボタンを**右クリック**し、「ターミナル**（管理者）**」を選びます。
2. 次を実行します。

   ```powershell
   wsl --install
   ```

3. 終わったら PC を**再起動**します。
4. 再起動後に Ubuntu の画面が開いたら、ユーザー名とパスワードを決めてください
   （パスワードは打っても画面に出ませんが、入力はされています）。
   画面が開かない場合は `root` だけが作られた状態で、そのまま使えます。

> 「この操作には管理者権限が必要です」と出たら、手順 1 のとおり
> **管理者のターミナル**から開き直してください。
> 会社や学校の PC で管理者になれない場合は、オンライン解析のみでお使いください。

### 6. 星図データを置く

C ドライブの直下に `AstrometryData` フォルダーを作り
（＝ `C:\AstrometryData`）、必要な zip を
[配布ページ](https://cloud.akashi-kosaku.uk/s/M2sNsnA2K4oJ4Co)
から落として **`C:\` の直下に展開**します。
`C:\AstrometryData\index-5205-00.fits` のようになれば正解です。

**使う望遠鏡の画角によって必要なものが変わります。**
大事なのは**「短いほうの辺」の画角**です。星の並び（四角形）は
短辺に収まる大きさまでしか作れないので、必要な段は短辺で決まります
（切り出していない普通の画像でも同じです）。

| zip | 対応する画角 | ASI290MM 全画面での焦点距離 | サイズ |
|---|---|---|---|
| `AstrometryData.zip`（基本セット） | 11′ 〜 2000′ | 〜 990 mm | 869 MB |
| `AstrometryData-index-5204.zip` | 8′ 〜 11′ | 990 〜 1360 mm | 868 MB |
| `AstrometryData-index-5203.zip` | 5.6′ 〜 8′ | 1360 〜 1950 mm | 1.7 GB |
| `AstrometryData-index-5202.zip` | 4′ 〜 5.6′ | 1950 〜 2730 mm | 3.4 GB |

短辺の画角は `画像の高さ[px] × 206.265 × 画素サイズ[µm] ÷ 焦点距離[mm] ÷ 60` 分角です。
足りないときは、解析に失敗したときの画面が必要なファイル名を教えてくれます。

> **実測した例。** 焦点距離 818 mm・968 × 548 画素（普通の 16:9）の画像は、
> 横幅 23.6′ なので `index-4107`（22′〜30′）で足りるはずでした。
> ところが 120 秒かけても解けず、短辺 13.4′ に合う `index-5205`（11′〜16′）を
> 足したら **10 秒で解けました**。

### 7. 解析エンジンを入れて設定する

PowerShell（管理者でなくて構いません）で、ノートブックを置いたフォルダーへ移動して
同梱のスクリプトを実行すると、`astrometry.net` の導入から設定・疎通確認まで
まとめて済みます。

```powershell
cd $env:USERPROFILE\Desktop\zahyou
powershell -ExecutionPolicy Bypass -File dev\setup_wsl.ps1
```

> 日本語環境の Windows では区切りが **￥**（円マーク）で表示されることがあります。
> **\\**（バックスラッシュ）とまったく同じ文字で、見た目が違うだけです。

手で進めたい場合は次の 2 つだけです。

```bash
# Ubuntu で
sudo apt update && sudo apt install astrometry.net -y
```

```powershell
# PowerShell で（星図データの置き場所をエンジンに教える）
wsl -u root bash -c "printf 'inparallel\ncpulimit 300\nautoindex\nadd_path /mnt/c/AstrometryData\n' > /etc/astrometry.cfg"
```

## ノートブック版の使い方

1. **セル A** を実行（準備。開いた最初の 1 回だけ）
2. **セル B** を実行してボタンで画像を選ぶ
3. **セル C** に目標を書いて実行 → すぐ下に結果と矢印が出ます

2 回目からは**セル C だけ**を実行し直せば十分です。
別の画像に変えるときは、セル B で選び直してからセル C を実行します。

画面が長いと感じたら、**コードの行の左はし**にマウスを近づけると出る `∨` を押してください。
その行から下のひとかたまりが 1 行に縮み、左は `>`、行末は `⋯` になります（もう一度押すと開きます）。
畳んでも実行される中身は変わりません。
なお、実行ボタン `▷` のすぐ右にある `∨` は「デバッグ」のメニューで、折りたたみではありません。

書き換えるのはセル C だけで、よく使うのは次の 3 つです。

| 設定 | 意味 |
|---|---|
| `INPUT_MODE` | 目標を天体名で指定（`'STAR_NAME'`）／赤経赤緯で指定（`'COORDS'`）／目標を決めない（`'NONE'` = 完全ブラインド。画像の向きだけ求めます）|
| `TARGET_STAR_NAME` | 目標の天体名。UCAC4 や TYC などのカタログ名、一般的な名前が使えます |
| `FOCAL_LENGTH_MM` | 望遠鏡の焦点距離。**書かなくても動きます**が、書くとオフラインが速く確実になります |

出力のいちばん大事なところは、図の下に出るこの 3 行です。

```
  画像中心から目標までのずれ
    全角距離      : 1.583'  (95.0")
    赤経(RA) 方向 : 0.918' 東へ
    赤緯(Dec)方向 : 1.290' 北へ
```

この例なら、赤経を東へ 0.92 分角、赤緯を北へ 1.29 分角動かせば目標が中心に来ます。

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| 目標がどこにあるか分からない | 目標を `'NONE'`（exe なら「指定しない (完全ブラインド)」）にすると、画像の向きだけを求められます |
| 画面を切り出していて解けない | 星の並びは**短いほうの辺**に収まる大きさまでしか作れません。短辺の画角に合う星図データが要ります（マニュアル 6 章） |
| 「画像が選ばれていません」 | セル B のボタンで選ぶか、セル C の `IMAGE_PATH` にパスを直接書く |
| 解析に失敗する（星が少ない） | 露出を伸ばす・ピントを合わせる・雲を確認する。画面に「星を◯個検出」と出ます |
| 解析に失敗する（画角が合わない） | 手順 6 の表を見て星図データを追加する。失敗時のメッセージに必要なファイル名が出ます |
| `zahyou_engine.py` が見つかりません | ノートブックと同じフォルダーに置く |
| オフラインで「WSL が使えません」 | 手順 5 をやり直す。管理者のターミナルでないと入りません |
| オフライン解析がとても遅い | `FOCAL_LENGTH_MM` を書くと探索範囲が決まり、大幅に速くなります |

さらに詳しくは
[マニュアル v3](天体画像解析プログラム「zahyou」導入・運用マニュアルv3.pdf)
の 7 章をご覧ください。
